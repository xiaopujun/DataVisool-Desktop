# 从 LCP 迁移项目

简体中文 | [English](../en/migration.md)

## 适用场景

本文面向已经使用 LCP 制作项目、希望将项目导入 DataVisool 继续编辑和使用的用户，以及需要处理项目中自定义服务器组件的开发者。迁移以 LCP 导出的项目 ZIP 为起点；组件源码依赖的调整另见 [包结构迁移说明](./package-migration.md)。

DataVisool 是独立的桌面应用，导入时会转换可识别的旧项目格式和配置。导入成功表示项目数据已写入，并不保证所有组件、外部服务和交互都能正常运行。

本文描述当前代码实现的范围。旧包兼容是临时能力，未来版本计划移除，具体移除时间尚未确定。迁移后请验证项目并使用 DataVisool 重新导出备份。

## 先判断你的情况

| 手头的内容或项目情况 | 建议做法 | 迁移结果的边界 |
| --- | --- | --- |
| 有 LCP 导出的项目 ZIP，包格式符合下文要求，项目主要使用受支持的内置组件 | 按下面的步骤导入空项目，再逐项检查 | 可以尝试自动导入；通过格式校验不等于画布、数据和交互都与原项目一致。 |
| 项目包含自定义服务器组件、动态脚本或旧地图配置 | 先导入验证；遇到不能转换的组件，按下文修改源码并重新构建 | 仅已识别的旧组件接口会在导入时转换；不能保证旧脚本、样式、地图及运行时行为完全兼容。 |
| 项目依赖公共 API、数据库、外部资源或网络服务 | 检查导出包和目标环境，在导入后重新测试连接 | 包外文件、数据库中的业务数据和外部服务不会随项目一起迁移；同引用标识的公共配置还可能被更新。 |
| 只有 LCP 的应用目录、数据库或项目截图，没有可导出的 ZIP | 回到 LCP 导出项目；如无法导出，需要人工重建 | 当前没有受支持的自动迁移入口，不能直接将旧应用目录当作项目导入。 |
| ZIP 缺少清单、格式或加密方式不受支持，或文件不完整 | 检查原始导出，必要时从 LCP 重新导出 | 导入器会拒绝不符合要求的包，不能保证所有 LCP 版本的导出包都能迁移。 |

## 迁移前准备

1. 在 LCP 中导出需要迁移的项目 ZIP，保留原项目和原始导出包。若有导出警告，先检查是否缺少图片、视频、字体、组件或数据源。
2. 安装 DataVisool；在项目列表中新建一个空项目并进入编辑器。导入会写入当前目标项目，使用空项目可避免覆盖已有项目数据。
3. 如果旧包已加密，准备导出时设置的口令。项目包可能包含接口地址、请求头、数据库连接信息等敏感内容，请妥善保管。
4. 在编辑器右上角的更多操作菜单中选择“导入项目”，选择 ZIP。明文包的导入口令可留空；整包加密或历史字段加密包需要正确口令。
5. 导入完成后检查画布、资源、数据和交互，再用 DataVisool 导出新的项目包作为备份。

导入还可能添加资源记录，并按引用标识复用或更新公共 API、公共数据库配置；它们可能被其他项目使用。已有重要数据时，请先备份，并检查导入后的公共数据源。

**目标项目影响**：导入会将项目数据写入当前编辑的项目，而不是创建一个完全独立的新项目；不要在尚未备份的已有项目中尝试。对于版本 3 的项目包，入口项目写入当前项目，包中其他项目节点会创建为新项目，项目层级和已识别的引用按包内信息恢复。

## 支持的项目包

| 情况 | 当前处理 |
| --- | --- |
| LCP 导出的项目 ZIP | 支持格式标记为 `light-chaser-project`、内部 manifest 的 `formatVersion` 为 2 或 3 的包，仍须通过结构和文件校验。版本 2 按单个项目导入；版本 3 按包内项目节点恢复项目结构和引用。 |
| DataVisool 项目 ZIP | 同一导入入口也识别 `datavisool-project` 格式；当前明文项目 manifest 支持版本 2 和 3。 |
| 支持的整包加密 | 支持 `package` 模式、`passphrase-v1` 算法的包；输入正确口令后，还需校验解密后的内部项目包。整包加密外层 manifest 可使用版本 4，这与内部项目 manifest 的版本是两回事。 |
| 历史字段级加密 | 支持已实现格式的公共 API 和数据库字段加密；需要正确口令。 |
| 旧项目压缩数据 | 导入时识别 `LCPZ1:gzip:` 标记，解压后再转换和保存。 |

这不是对所有 LCP 版本的承诺：没有 `manifest.json`、格式标记不受支持、内部 manifest 版本低于 2 或高于 3，或包缺失必要文件、校验不通过时，当前导入器会拒绝导入。其他加密算法也不受支持。这里的 `formatVersion` 指项目包格式版本，不是 LCP 应用版本号。

**如何初步判断包格式**：可以用压缩软件只读查看 ZIP 根目录的 `manifest.json`，查找 `format` 和 `formatVersion`；不要修改后再导入。明文包可直接查看内部清单；整包加密时，外层清单版本与解密后的内部项目清单版本是两个概念，不能只凭外层版本判断内部项目是否受支持。最终结果以导入时的解密、结构和文件校验为准。

## 项目内容与资源

| 内容 | 当前处理和边界 |
| --- | --- |
| 画布、图层和配置 | 导入项目 JSON；能否正常显示取决于组件及其配置是否仍受支持。对于未识别的历史结构，不保证自动修复。 |
| 已识别的旧配置 | 导入时转换旧静态数据包装；将循环容器旧 `gap` 转换为水平、垂直间距；将基础表格旧滚动配置转换为当前轮播配置。用户数据中的同名字段不会作为配置转换。 |
| 图片、视频 | 包内列出的资源会导入；能与包内资源匹配的旧本地 `asset://localhost/` 或 `http://asset.localhost/` 地址会改写为新应用地址。包中没有的文件不会凭旧机器路径自动恢复；视频能否播放还取决于平台支持的编码。 |
| 字体、3D 模型 | 支持导入清单中列出的字体和模型资源；模型入口和依赖文件需完整。导入后仍需检查字体效果和模型显示。 |
| 动态脚本 | 支持导入清单中的本地脚本和远程脚本地址；版本 3 可恢复包中记录的项目级归属。远程脚本仍需目标网络能访问，脚本依赖旧接口时不保证可用。 |
| 公共 API、公共数据库 | 支持导入包内记录并重写已识别的项目引用；无法映射的引用会被清空，导入后提示重新选择。同一引用标识可能复用并更新现有配置。只迁移连接配置，不迁移外部数据库中的数据；连接、权限和网络需要重新验证。 |
| 蓝图、子项目与大屏引用 | 蓝图数据随项目数据导入，效果需逐项验证。版本 3 项目图支持恢复包内项目层级并重写已识别的大屏引用；缺少被引用的项目时可能失败。版本 2 只按单项目路径导入，不提供版本 3 的项目图恢复。 |
| GIS 地图 | 旧地图配置没有完整的导入转换保证；尤其是旧的 `sources` 对象、`urlTemplate` 和旧图层内联结构，需在导入后检查，必要时按当前组件格式重新配置。 |

资源地址重写只针对导入器能匹配到的包内静态资源；外部 URL 不会变成包内文件。即使 ZIP 导入成功，仍应逐一检查资源显示和播放。

## 用户开发的服务器组件

导入项目包时，DataVisool 会对包内旧服务器组件做**静态转换**：分析组件脚本中可识别的旧接口和注册标记，改写为当前宿主入口；导入阶段不会执行组件脚本。该处理面向满足条件的用户组件，不依赖是否存在同名示例组件。单个 `.js` / `.mjs` 文件和包含入口脚本的组件 ZIP 均有对应处理。

当前可以转换的旧接口成员如下：

| 旧接口 | 可识别的成员 |
| --- | --- |
| `LightChaserInterface` | `AbstractDesignerController`、`AbstractDesignerDefinition`、`BaseInfo`、`AnimationConfig`、`ThemeConfig`、`DataConfig`、`FilterConfig` |
| `LightChaserUtil` | `ObjectUtil`、`ComponentUtil` |

转换还要求组件采用转换器能识别的直接函数调用结构，且旧组件注册位置唯一。组件 ZIP 中需要转换的旧代码必须位于选出的唯一入口文件；其他脚本文件中出现需要转换的旧代码会导致导入失败。

以下情况**不支持自动静态转换**，导入器会拒绝可识别的不安全或不明确用法：

- 使用上表之外的旧接口成员，或使用 `LightChaserUI`、`LCPSDK`、`LCPTypes`、`LCPUI` 等旧全局接口。
- 使用无法静态确定的动态属性、动态执行代码、解构入口参数、同名遮蔽，或把整个旧接口对象传给其他代码。
- 脚本无法解析、入口或注册位置不符合要求，或组件包没有可用的 JavaScript 入口。

转换只改写已识别的接口引用，并不证明组件行为与旧环境完全一致。旧组件依赖未识别的接口、外部脚本、资源或旧运行时行为时，仍可能无法运行。无法转换的组件需要修改源码以使用当前 SDK/UI，用新版 CLI 重新构建；具体入口见 [包结构迁移说明](./package-migration.md)。如果旧组件使整个项目包无法导入，可以在保留原项目备份后，从 LCP 项目中移除该组件并重新导出；导入成功后上传新版组件，手动恢复组件配置和相关蓝图。单独上传旧组件不是上述项目包导入转换的替代入口。

## 不支持自动迁移的内容

- **旧应用本地数据**：不直接读取或升级 LCP 的应用数据目录、数据库和工作区；项目需要先从 LCP 导出 ZIP。无法导出项目包时，没有受支持的自动迁移路径。
- **应用级设置与状态**：旧快捷键、偏好设置、AI 模型配置和密钥、Agent 历史及任务状态不通过项目包自动迁移，需要在新应用中重新配置。
- **旧剪贴板内容**：旧应用复制的数据不能作为新应用剪贴板数据直接粘贴。
- **包外内容**：项目包中没有包含的本地资源、外部数据库数据、外部服务和依赖不会被自动补齐。
- **反向迁移**：DataVisool 新导出的项目包不保证能被 LCP 导入，新服务器组件也不保证能在旧宿主运行。

## 导入后的检查

1. 对照原项目检查画布布局、图层、文字、表格、循环容器及地图。
2. 检查图片、视频、字体和 3D 模型；若资源缺失，回到原项目补齐后重新导出。
3. 测试公共 API、数据库、WebSocket 等数据连接，确认目标机器上的地址、凭据和权限可用。
4. 逐一测试蓝图事件、子项目、大屏引用、动态脚本和自定义服务器组件。
5. 确认无误后，使用 DataVisool 导出新项目包，并保留原始 LCP 包作为备份。

## 常见问题

| 现象 | 如何处理 |
| --- | --- |
| 提示找不到 `manifest.json`，或格式、版本不受支持 | 确认选择的是 LCP 导出的项目 ZIP，而不是单个组件 ZIP、备份目录或重新打包后的文件；检查清单标记与版本，必要时回到 LCP 重新导出。不能保证重新导出一定能得到受支持的格式。 |
| 提示缺少口令或解密失败 | 确认使用导出时的口令，检查包是否损坏；未知口令或不受支持的加密算法无法通过此入口自动恢复。 |
| 提示文件缺失或校验失败 | 保留原包，在 LCP 检查资源是否完整后重新导出；不要手工修改包内文件来绕过校验。 |
| 提示项目结构不完整或引用的项目缺失 | 回到 LCP 检查子项目和大屏引用是否包含在导出范围内，再重新导出；版本 2 包不具备版本 3 的项目图恢复能力。 |
| 提示“服务器组件无法静态转换” | 按错误中的组件名和接口检查源码，参考[包结构迁移说明](./package-migration.md)修改并重新构建；必要时先在旧项目移除该组件再导出，导入后手动恢复配置与蓝图。 |
| 导入成功，但提示数据源需要重新选择 | 在 DataVisool 中重新选择公共 API 或数据库，核对地址和凭据，再测试连接。导入成功不表示这些引用已自动恢复。 |
| 导入成功，但显示或交互与 LCP 不一致 | 逐项检查资源、组件配置、地图、脚本和蓝图；按当前组件能力调整。保留原项目以便对照，不能假设导入会自动修复所有历史行为。 |

仅有导入成功提示不能替代上述检查。
